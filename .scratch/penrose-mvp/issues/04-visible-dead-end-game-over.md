# 04: 可見死局與遊戲結束

**What to build:** 當可放置範圍內的某個邊界凹角或凹洞，對每種拼塊的每個方向試放後都不合法時，就是可見死局。如果死局是預放造成的，凹洞立刻標紅，但遊戲不結束，玩家可以修正；如果玩家不修正、直接放下下一片，遊戲在確認時結束，結算不計那片新的拼塊。結束時跳出最簡版結算窗，顯示面積（以平方長度單位計）和片數，並提供開新局。

**Blocked by:** 03 預放：換方向、移除、自動確認

**Status:** resolved

- [x] 引擎能回報可見死局的位置，並區分「預放造成、尚未確認」和「已確認、遊戲結束」（有測試）
- [x] 預放造成死局時，凹洞標紅，遊戲仍在進行；改方向或移除後，標紅消失（有測試）
- [x] 判定時序：放下新的一片時，先確認前一片預放，再檢查已確認鋪砌；有死局就結束，而且分數不計新的那一片（有測試）
- [x] 面積分數等於已確認鋪砌各拼塊面積的總和，kite 與 dart 的面積比為 φ（有測試）
- [x] 遊戲結束後，引擎拒絕所有放置指令
- [x] 性質測試：以多個隨機種子反覆「隨機挑一個候選放置放下」直到死局，過程中始終不重疊、相鄰邊都符合匹配規則、每個內部頂點都屬於 7 種頂點組態之一
- [x] 最簡版結算窗：面積、片數、開新局

## Notes (implementation)

- 判定單位是邊界邊：某條邊界邊上，任何拼塊的任何方向都無法合法貼上，就是可見死局（凹洞的每條邊都會被標出）。合法性只會隨拼塊增加而變嚴，所以這種邊永遠補不起來。「完全沒有任何候選放置」時每條邊界邊都是死邊，自動涵蓋。成長圓（ticket 05）尚未實作，目前檢查整條邊界。
- 引擎 API：`status()`、`deadEnds()`（`{from, to, cause: 'pending' | 'confirmed'}`）、`score()`（`{tiles, area}`，只計已確認鋪砌）、事件 `game-over`。盤面上有死局時放下下一片：確認預放、遊戲結束、新的一片不加入，`place` 回傳 true。
- 結算窗：`src/ui/GameOverDialog.svelte`，文字集中在 `text` 物件，方便 ticket 13 移入 i18n。
