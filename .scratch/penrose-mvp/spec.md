# Penrose Tiling Game MVP

Status: ready-for-agent

設計依據：`docs/penrose-tiling-game-design.md`（訪談定案）、`docs/adr/0001-ui-framework-svelte-5.md`。互動原型：`docs/penrose-tiling-game-visual.html`。

## Problem Statement

Penrose tiling 理論上可以無限鋪滿平面，但每一步即使都符合匹配規則，仍可能把局面推向之後無法延伸的死路。玩家想要一款把這個特性變成玩法的遊戲：在瀏覽器或手機上一片一片地拼接，盡量拼得越大越好；一旦拼出一個肉眼可見、任何拼塊都放不進去的凹洞就輸，而鋪砌的大小就是這局的分數。目前沒有任何現成的遊戲能這樣玩、能在手機上安裝，也沒有任何一款會在輸了之後告訴玩家「其實你早在哪一步就已經註定失敗」。

## Solution

一款 PWA 遊戲，第一版使用 P2（kite/dart）拼塊組。每局從隨機的開局圖形開始，玩家只能做符合匹配規則、且位於成長圓內的放置。最新放下的一片是預放，在放下一片之前都還能換方向或移除。一旦已確認鋪砌出現可見死局，遊戲就結束。

玩家可以隨時在兩種模式之間切換：自由模式是自己挑拼塊、自己找位置；心流模式由系統沿著邊界連續推薦最受限的位置。兩種模式的分數相同，主分數是覆蓋面積，以拼塊組最短邊為 1 個長度單位。

結束時先跳出結算窗，再由「詳細」進入分析頁，內容包括使用統計、形狀完整度，以及錯誤回溯重播。棋譜會自動存在本機，所以關掉 App 也能接著玩；棋譜也能匯出成連結或檔案分享。介面提供繁體中文與英文，字型使用子集化並改名後的 LINE Seed。

## User Stories

### 開局

1. As a 玩家, I want 每局從隨機抽出的開局圖形開始, so that 每一局的起點都不一樣、不會覺得重複。
2. As a 玩家, I want 開局圖形保證本身是合法的 Penrose 鋪砌, so that 我不會一開局就已經註定失敗。
3. As a 玩家, I want 開局圖形只有 3 到 6 片, so that 我能很快接手，而且開局佔分數的比例很小。
4. As a 玩家, I want 開局時畫面自動置中並縮放到開局圖形, so that 我不必先找盤面在哪裡。
5. As a 玩家, I want 隨時可以開新局, so that 我能放棄一局重新挑戰。

### 放置規則

6. As a 玩家, I want 系統只接受符合匹配規則的放置, so that 我不會因為看錯標記而放出非法的拼塊。
7. As a 玩家, I want 新的拼塊至少要和現有鋪砌共用一整條邊, so that 鋪砌始終連成一塊。
8. As a 玩家, I want 盤面上用淡淡的圓顯示可放置範圍（成長圓）, so that 我一眼就知道現在能在哪裡放。
9. As a 玩家, I want 成長圓隨鋪砌面積變大而長大, so that 我只要填滿圓內的區域，就能繼續往外擴張。
10. As a 玩家, I want 成長圓外的邊界即使形狀合法也不能放, so that 我無法一直往單一方向延伸、躲開自己留下的死路。
11. As a 玩家, I want 不合法或在範圍外的位置不會出現吸附預覽, so that 我不會誤以為那裡可以放。

### 自由模式：滑鼠

12. As a 滑鼠玩家, I want 先從托盤點選 kite 或 dart, so that 我能先決定心裡想放的那一片。
13. As a 滑鼠玩家, I want 移動游標時，最近的候選放置會顯示預覽, so that 我看得到拼塊會放在哪裡、朝哪個方向。
14. As a 滑鼠玩家, I want 用滾輪在該位置的合法方向之間循環, so that 我能快速換方向，又不必轉過不合法的方向。
15. As a 滑鼠玩家, I want 左鍵放下拼塊, so that 放置只要一個動作。
16. As a 滑鼠玩家, I want 滑鼠移到預放上時，用滾輪也能換它的方向, so that 放下之後還能修正。
17. As a 滑鼠玩家, I want 在預放上按右鍵就能移除它, so that 我能收回剛放的那一片。

### 自由模式：觸控

18. As a 觸控玩家, I want 單指從托盤拖出拼塊, so that 只用一根手指就能操作。
19. As a 觸控玩家, I want 拖曳時預覽顯示在手指上方, so that 手指不會擋住吸附的位置。
20. As a 觸控玩家, I want 放開手指時拼塊就吸附成預放, so that 放置的動作很自然。
21. As a 觸控玩家, I want 點擊預放就能循環切換它的合法方向, so that 不必到別處找按鈕。
22. As a 觸控玩家, I want 把預放拖回托盤就能移除它, so that 收回的手勢很直覺。
23. As a 觸控玩家, I want 在空白盤面上單指拖曳是平移、雙指是縮放, so that 我能在大鋪砌上移動視角。

### 預放與確認

24. As a 玩家, I want 放下下一片時，前一片自動確認，而不是另外點確認按鈕, so that 操作流暢，也不必去點別處的按鈕。
25. As a 玩家, I want 已確認鋪砌永遠不能再更動, so that 遊戲有真正的取捨，而不是可以無限悔棋。
26. As a 玩家, I want 預放如果造出可見死局，凹洞會立刻標紅, so that 我有機會在確認前修正這個明顯的錯誤。
27. As a 玩家, I want 預放造成死局但我沒修正就放下下一片時，遊戲立即結束, so that 規則前後一致。
28. As a 玩家, I want 遊戲結束時，結算不計那片觸發確認的新拼塊, so that 分數反映的是結束當下的已確認鋪砌。

### 可見死局

29. As a 玩家, I want 只有在看得見的凹洞或凹角，連一片合法拼塊都放不進去時才判輸, so that 我輸得心服口服，不會因為演算法看見的遠端矛盾而莫名其妙地輸掉。
30. As a 玩家, I want 死局的位置在畫面上被清楚標出, so that 我知道自己輸在哪裡。
31. As a 玩家, I want 成長圓內完全沒有任何候選放置時，也視為死局, so that 遊戲不會卡在一個不能動也不會結束的狀態。

### 心流模式

32. As a 玩家, I want 隨時在自由模式與心流模式之間切換，而且不會影響目前這局, so that 我累了或想加快節奏時可以換一種玩法。
33. As a 心流模式玩家, I want 系統標出一個推薦位置, so that 我不必在盤面上找下一步要放哪裡。
34. As a 心流模式玩家, I want 推薦位置優先選在上一片附近最受限的凹處, so that 視線和手幾乎不用移動。
35. As a 心流模式玩家, I want 附近沒有凹處時，系統才挑離上一片最近的凹處, so that 推薦點沿著邊界連續前進，不會亂跳。
36. As a 心流模式玩家, I want 畫面只在推薦點快要離開可視範圍時才平滑地平移, so that 畫面的連續性不被打斷。
37. As a 心流模式玩家, I want 選了拼塊之後，預放直接吸附到推薦位置，我只要挑方向, so that 我只做真正需要判斷的決定。
38. As a 心流模式玩家, I want 心流模式下依然可能犯錯而輸, so that 分數仍有意義。

### 外觀與顯示

39. As a 玩家, I want 自訂 kite、dart 和背景的顏色, so that 盤面符合我的喜好。
40. As a 玩家, I want 從幾組 preset 配色中選一組, so that 不用自己調色也能有好看的盤面。
41. As a 玩家, I want 預設顯示 Conway 弧線，顏色由配色自動推導成對比色, so that 我能看懂拼塊為什麼能放或不能放。
42. As a 進階玩家, I want 在設定中關掉弧線, so that 我能看單純的形狀圖樣，或把它當成困難模式。
43. As a 玩家, I want 設定在下次開啟時仍然保留, so that 不必每次重新設定。
44. As a 玩家, I want 在繁體中文與英文介面之間切換, so that 不懂中文的朋友也能玩。
45. As a 玩家, I want 介面文字使用統一的 LINE Seed 風格字型，中英文混排也很協調, so that 遊戲看起來有完整的品牌感。
46. As a 玩家, I want 在高解析度的手機螢幕上，拼塊邊緣依然清晰, so that 畫面不會模糊。
47. As a 玩家, I want 鋪砌長到上千片時，平移和縮放仍然流暢, so that 越玩越大也不會卡頓。

### 計分與結算

48. As a 玩家, I want 主分數是覆蓋面積，以平方長度單位計, so that kite 和 dart 用得多或少都不會影響公平性。
49. As a 玩家, I want 遊戲結束時跳出結算窗，顯示面積、片數和個人最佳的比較, so that 我能立刻知道這局打得如何。
50. As a 玩家, I want 結算窗告訴我「最遲在第 N 步就已註定」, so that 我知道真正犯錯的時間點，可能遠早於結束那一步。
51. As a 玩家, I want 從結算窗按「詳細」進入分析頁, so that 想深入了解的時候才看更多資訊。
52. As a 玩家, I want 每個拼塊組有各自的個人最佳, so that 不同難度的拼塊組不會混在一起比較。
53. As a 玩家, I want 分數不區分自由或心流模式, so that 切換模式不會有心理負擔。

### 分析頁

54. As a 玩家, I want 看到片數、總面積，以及 kite 與 dart 的比例（並與理想值 φ 比較）, so that 我了解自己這局的組成。
55. As a 玩家, I want 看到形狀完整度：完整半徑，以及面積與同面積圓的接近程度, so that 我知道自己拼得是否整齊。
56. As a 玩家, I want 錯誤回溯重播，標出局面最遲在哪一步就已註定失敗，以及最後死局的位置, so that 我能從失敗中學習。
57. As a 玩家, I want 錯誤回溯的文字寫「最遲在第 N 步」，而不是「就在第 N 步」, so that 我不會被近似的結果誤導。
58. As a 玩家, I want 能逐步播放、暫停和拖動重播進度, so that 我能仔細看局面是怎麼演變的。
59. As a 玩家, I want 分析頁附帶顯示這局「自由 X% / 心流 Y%」, so that 我能參考自己的玩法習慣。

### 存檔、續玩與分享

60. As a 手機玩家, I want 每放一片或改一次方向都自動保存, so that 接電話或 App 被系統關掉都不會失去這局。
61. As a 玩家, I want 重開 App 時直接回到原本的局面，包含預放, so that 我能無縫接著玩。
62. As a 玩家, I want 沒有手動存檔和讀檔, so that 沒有人能靠讀檔來反悔，分數才有公信力。
63. As a 玩家, I want 把一局的棋譜匯出成分享連結, so that 朋友點開就能重播我這局。
64. As a 玩家, I want 棋譜太長、連結放不下時，改成匯出檔案, so that 再大的局也能分享。
65. As a 收到分享的人, I want 開啟分享連結或檔案後，能看到該局的完整重播與分析, so that 我能欣賞別人的鋪砌，學習他的作法。
66. As a 玩家, I want 本機保留最近幾局的棋譜, so that 我能回頭看自己的紀錄。

### PWA 與平台

67. As a 手機玩家, I want 把遊戲加入主畫面，以全螢幕的 App 形式開啟, so that 它用起來像原生 App。
68. As a 玩家, I want 第一次載入後就能離線遊玩, so that 沒有網路也能玩。
69. As a 手機玩家, I want 第一次載入很快, so that 不必等字型或大型套件下載。
70. As a 玩家, I want 電腦瀏覽器和手機都能玩, so that 在哪裡都能接著挑戰。
71. As a 玩家, I want 在「關於」頁看到字型出處與授權說明, so that 遊戲尊重它所使用的開源資源。

### 開發者

72. As a 開發者, I want 規則引擎和畫面完全分離，而且可以獨立測試, so that 最難寫對的規則邏輯能被快速而確定地驗證。
73. As a 開發者, I want 拼塊組以通用的抽象實作, so that 之後加入 P3 等拼塊組時，不必重寫規則引擎。
74. As a 開發者, I want 棋譜帶有格式版本號，並且能確定性地重播, so that 日後要加線上排行榜時，伺服器可以用同一個引擎重算分數驗證。
75. As a 開發者, I want 字型子集由建置步驟依語系檔自動產生並改名, so that 新增介面字串時不會缺字，也不違反保留字型名稱的條款。

## Implementation Decisions

### 模組

- **規則引擎（深模組，唯一的測試切入點）**：純 TypeScript，不依賴 DOM、Canvas 或 Svelte，對外提供一組「指令與查詢」介面，畫面層只透過它和遊戲互動。
  - 指令：以拼塊組與隨機種子開新局；選擇拼塊；放下拼塊（成為預放，同時確認前一片預放）；循環切換預放的方向；移除預放；切換模式。
  - 查詢：目前鋪砌（已確認鋪砌與預放分開）；給定位置附近的候選放置，以及某位置的合法方向清單；成長圓（圓心與半徑）；可見死局的位置（區分「預放造成、尚未確認」和「已確認、遊戲結束」）；心流推薦位置；遊戲狀態（進行中或已結束）；分數與統計；棋譜。
  - 引擎在每個指令之後發出事件（例如鋪砌變更、死局出現、遊戲結束），讓介面層訂閱。
- **拼塊組定義**：P2 的拼塊幾何（短邊 1、長邊 φ；kite 的角是 72°、72°、72°、144°，dart 的角是 36°、72°、36°、216°）、匹配規則（Conway 弧線或頂點標記），以及 7 種頂點組態圖鑑，都以資料加上少量函式描述，讓規則引擎可以對任何拼塊組通用。
- **精確幾何**：頂點座標以 ℤ[φ] 係數（a + bφ 的形式）配合 10 個方向的單位向量表示，判定時不使用浮點數比較；浮點數只用在繪圖。這是確定性重播與日後伺服器驗證的前提。
- **開局產生器**：把 P2 參考鋪砌以細分（deflation）產生到足夠大，依種子挑一個中心，取 3 到 6 片相連的拼塊。由同一個種子產生的開局圖形必須完全相同。
- **錯誤回溯分析**：輸入棋譜，以強制拼塊傳播（反覆補上只剩一種可能的位置，推演到矛盾為止）逐步回放，找出最早一個已經註定失敗的步驟，作為「最遲在第 N 步」的近似答案。分析只在結束後離線執行，不影響遊戲當下的判定。
- **棋譜編解碼**：棋譜帶有格式版本號，內容包括拼塊組 id、開局圖形（或可重現它的種子與參數）、每一步的拼塊種類、所接的頂點或邊、方向、模式，以及預放的修改與移除。提供兩種序列化：一是壓縮後放進網址 fragment 的文字形式，二是檔案形式。解碼後重播的局面必須與原局完全相同。
- **持久化層**：用 IndexedDB 附加寫入每一步，預放的變動只覆寫一筆「目前預放」的紀錄；儲存個人最佳（按拼塊組分開）、最近幾局的棋譜，以及設定（配色、弧線開關、語言）。續玩時以引擎重播棋譜來還原局面。
- **盤面繪製層**：Canvas 2D，負責 devicePixelRatio、視窗外裁切、相機（平移、縮放、平滑移動），以及在鋪砌很大時把已確認鋪砌畫進離屏快取的圖塊。另外畫出成長圓、預覽、預放、死局標紅、心流推薦點、Conway 弧線。
- **輸入層**：把滑鼠與觸控事件轉成引擎指令與相機操作，包括點選托盤、最近候選放置的命中判斷、滾輪循環方向、左鍵放下、右鍵移除；觸控則是單指拖出、預覽畫在手指上方、放開即吸附、點擊循環、拖回托盤移除、單指平移、雙指縮放。
- **介面層（Svelte 5，見 ADR 0001）**：托盤、模式切換、設定面板（配色、preset、弧線開關、語言）、結算窗、分析頁（統計、比例、形狀完整度、重播控制）、關於頁。引擎事件透過 `$state` 接進介面。對話框用原生 `<dialog>`，分數動畫用 NumberFlow 的 Svelte 版，圖表手寫 SVG。
- **i18n**：所有介面字串集中在語系檔（zh-TW、en）。
- **字型建置步驟**：讀取所有語系檔中的字元，把 LINE Seed Sans（EN，負責拉丁字母）與 LINE Seed TW（負責中文）子集化，改寫字型名稱表為專案自己的名稱，輸出 WOFF2，並附上 OFL 授權全文。只使用兩者共有的字重：Thin、Regular、Bold、ExtraBold。CSS 以 `unicode-range` 先讓 EN 處理拉丁字母，再讓 TW 處理中文。所選工具必須能改寫字型名稱表。
- **PWA**：用 vite-plugin-pwa 產生 manifest 與 service worker，預先快取應用程式與字型子集。

### 規則細節

- **候選放置**：一組（位置、拼塊、方向），必須符合匹配規則、不與既有拼塊重疊、至少和鋪砌共用一整條邊，而且位在成長圓內。
- **成長圓**：圓心是鋪砌的質心，半徑 R = √(面積/π) + 餘量。餘量是可調常數，靠試玩調整。質心要不要計入預放，在實作時依圓是否抖動決定，預設只用已確認鋪砌。
- **可見死局**：成長圓內有某個邊界凹角或凹洞，對每種拼塊的每個方向試放後都不合法；或者成長圓內完全沒有任何候選放置。
- **判定時序**：放下新的一片時，先確認前一片預放，再檢查已確認鋪砌（不含新預放）有沒有可見死局。有的話遊戲結束，結算時不計新放的那一片；沒有的話，再檢查新預放有沒有造成死局，有就把凹洞標紅，但遊戲不結束。
- **心流推薦**：在上一片附近（預設 2 個長度單位內）的凹處中，挑候選放置最少的一個；附近都沒有時，挑離上一片最近的凹處。半徑與相機平移門檻都是可調常數。
- **計分**：主分數是已確認鋪砌的總面積，以平方長度單位計（P2 的 dart ≈ 0.951、kite ≈ 1.539）。開局圖形計入面積。個人最佳按拼塊組分開，不區分模式。

## Testing Decisions

- **唯一的測試切入點是規則引擎的指令與查詢介面。** 測試以固定的種子與拼塊組開局，送出指令，再透過查詢斷言外部可見的結果。測試不得依賴引擎的內部資料結構、私有函式或演算法步驟，以後換掉資料結構或演算法時，測試應該不必改。
- **好的測試長這樣**：用描述局面的方式建立情境（某個開局，接著放這幾片），然後斷言玩家看得到的事實。例如：「這個位置的合法方向剛好是這兩個」「放下這片之後，這裡出現標紅的凹洞，但遊戲還在進行」「再放一片，遊戲結束，分數等於這些拼塊的面積總和」。
- **需要涵蓋的行為**：
  - 開局：同一個種子產生的開局圖形完全相同；開局片數在 3 到 6 之間；開局圖形本身沒有可見死局。
  - 候選放置：非法方向、與既有拼塊重疊、沒有共用邊、在成長圓外的放置，都不會出現在候選中。
  - 預放：換方向只在合法方向之間循環；移除後局面回到放下前；放下下一片會確認前一片。
  - 死局與判定時序：預放造成死局時標紅但遊戲不結束；確認後遊戲結束，而且分數不計新的那一片；成長圓內沒有任何候選放置時算死局。
  - 成長圓：面積增加時半徑跟著增加。
  - 心流推薦：推薦點優先落在上一片附近；附近沒有凹處時，挑最近的那一個。
  - 計分：面積等於各拼塊面積的總和；kite 與 dart 的面積比為 φ。
  - 棋譜：編碼後解碼並重播，結果與原局完全相同，包括預放的修改與移除；格式版本號被保留。
  - 錯誤回溯：在預先構造的棋譜中，回報的「最遲第 N 步」不晚於結束的那一步，而且對已知的局面能回報預期的步數。
- **性質測試**：用隨機種子讓引擎反覆執行「隨機挑一個候選放置放下」直到死局，斷言以下不變式始終成立：已確認鋪砌中沒有重疊、所有相鄰邊都符合匹配規則、每個內部頂點都屬於 7 種頂點組態之一、重播棋譜得到相同局面。
- **測試工具**：Vitest。
- **既有範例**：專案目前沒有任何測試或程式碼可以參考。互動原型中有一份可試玩的規則引擎雛形，可以參考它的幾何與匹配規則，但不能當作正確性的依據。
- **不寫單元測試的部分**：Canvas 繪圖、輸入層、Svelte 介面、持久化層、字型建置與 PWA 設定。這些都是薄的轉接層，靠手動試玩與原型對照來確認。

## Out of Scope

- P3 菱形，以及 P2 以外的其他拼塊組（但核心必須以通用的拼塊組抽象實作）。
- 依方向上色、依頂點組態上色。
- 頂點組態分布分析。
- 允許反悔多片的設定（只有預放那一片可以修改）。
- 線上排行榜、帳號、後端伺服器與防作弊。
- 繁體中文與英文以外的語言。
- 音效與音樂。
- 撤銷已確認的拼塊、手動存檔或讀檔。
