# 0001. 介面層使用 Svelte 5

- 狀態：已採納
- 日期：2026-10-23

## 背景

盤面繪製與規則引擎都用純 TypeScript 加 Canvas 2D 實作，不依賴任何框架，拖曳、吸附、滾輪轉向等手勢也都在 Canvas 這一層處理。框架只負責外圍介面：托盤、模式切換、設定面板、結算窗，以及分析頁。

這個專案是 PWA，第一次載入的大小會直接影響手機上的體驗。

## 決定

外圍介面使用 **Svelte 5**。遊戲引擎發出的事件透過 `$state` 物件接到介面。

搭配方式：

- 對話框（設定面板、結算窗）：用原生 `<dialog>`，自行處理焦點與關閉。
- 分數跳動動畫：用 NumberFlow 的 Svelte 版。
- 一般的過場：用 Svelte 內建的 `transition:`，需要更複雜的動畫時，用 motion 的原生 JS `animate()`。
- 分析頁的圖表：手寫 SVG。

## 考慮過的選項

- **Preact**：大小與 Svelte 相當，但要搭配 `@preact/signals` 接遊戲狀態才會一樣簡潔；透過 `preact/compat` 使用 React 套件時，可能會有相容性問題。
- **React**：可以完整使用 React 生態系的套件（base-ui 的無障礙對話框、motion 的元件寫法、recharts），但執行時大約多 40 KB。我們的介面很少，換這些套件不值得。

## 後果

- 放棄了 React 生態系的元件：base-ui、Sonner、recharts、cmdk，以及 motion 的元件寫法都不能用。對話框的無障礙行為（焦點鎖定、Esc 關閉、恢復焦點）要靠原生 `<dialog>` 加上自行測試。
- 框架只碰外圍介面，所以日後真的要換，影響範圍只限於介面元件，規則引擎與棋譜格式都不受影響。
